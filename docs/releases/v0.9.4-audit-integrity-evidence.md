## 結論

v0.9.4 建立可升級的 audit integrity substrate：受支援的 Agent filesystem／shell path action 無法直接以 `.council`、audit、sessions、sandbox config、reserved auth/grant path 或 project policy 為目標；audit 與 session persistence 在落盤前共用遞迴 secret redaction；新 audit event 有 schema version、serialized sequence、canonical content-derived event ID，result 精確引用 attempt event ID；loader 與 CLI 可區分 `empty`、`verified`、`legacy_unverified` 與 typed integrity failure。

這不是完整 hash chain 產品宣稱。每筆 event 的 SHA-256 ID 沒有 predecessor link、外部簽章或 anchored head；host owner／root、`run_tests` 執行的 project code、任意外部程序、刪除尾端 event 或整份替換為自洽 history 仍在保護範圍外。

## 威脅邊界

| Actor／路徑 | v0.9.4 結果 |
|---|---|
| Public filesystem tools | `.council` root／children、nested `.council/**` 與 root／nested `council.policy.yaml` 在 I/O 前 `denied_path` |
| Supported shell path actions | `cat`／`ls`／`rm`／`mv`／`cp`／`touch`／`mkdir` 的 control-plane operand 在 subprocess 前拒絕 |
| Project policy | `denied_paths` 與 built-in 仍採 union，不能移除 control-plane protection |
| Council runtime writers | Sandbox/session/audit writer 仍可經內部 API 寫入；這些不是 Agent product tool path |
| Host user／root／external process | 不在 product-tool boundary；本版不宣稱 OS isolation |
| `run_tests` project process | 仍可依 host 權限碰觸 workspace；不宣稱 denylist containment 該 process |

Built-in patterns同時保護 `.council` root，避免 `rm -rf .council` 藉由只指定父目錄繞過 child patterns。Workspace parent `.` 仍可列出 `.council` 這個名稱，但不能把該 control-plane root 當作 tool target。

## Redaction matrix

Redaction 在 truncation 前進行，輸出標記固定為 `[REDACTED]`；實際 tool argument／`ToolResult` 不會因 evidence sanitation 改變。

| 類型 | 規則／證據 |
|---|---|
| Sensitive keys | `api_key`、authorization、token variants、password/passphrase、secret/client secret、private key、credential、cookie 等 normalized key；整個 value 遮罩 |
| Credential text | `api_key=...`、`token: ...`、password／passphrase／secret assignment |
| Authorization | `Bearer ...` |
| Provider tokens | OpenAI/OpenRouter `sk-*`、GitHub token、Slack `xox*`、AWS access key、Google API key 常見 prefix |
| JWT | 三段 base64url token |
| Private key | PEM private-key block |
| Nested／fallback | dict/list/tuple 與非 JSON scalar fallback遞迴處理 |
| Legacy | load/show/export 再套 sanitation，狀態明示 `legacy_unverified` |

`test_recursive_redaction_precedes_truncation_and_preserves_ordinary_values` 與 `test_large_secret_is_redacted_without_leaking_prefix` 同時檢查漏遮罩、普通 path/count/message 保留及長 secret 不殘留 prefix。`test_session_persistence_redacts_and_retains_audit_linkage`、`test_session_links_exact_audit_events_and_redacts_all_result_fields` 覆蓋 prompt、args、metadata、output、error 與 middleware 實際 persistence。

Redaction 是明確 pattern substrate，可能誤遮罩 token-shaped benign text，也可能漏掉未來未知 secret 格式；不能宣稱任意秘密都可被識別。

## Canonical envelope、sequence 與 integrity detection

Schema-v1 event 新欄位：

- `schema_version: 1`
- `sequence`: log 中 v1 event 從 1 嚴格遞增
- `event_id`: `sha256:` + canonical JSON digest；canonical JSON 使用 UTF-8、sorted keys、compact separators，涵蓋 `event_id` 以外所有 persisted fields
- `attempt_event_id`: middleware result 精確引用 attempt

Allocation/append 在 per-path process lock 與 POSIX advisory lock 中完成；writer 在 lock 內驗證既有結構、配置下一個 sequence、建立 digest，以 append descriptor 寫一個 newline-terminated record並 `fsync`。`test_process_writers_allocate_one_contiguous_sequence` 以 4 個 spawned processes 寫 12 筆，結果為唯一且連續的 1–12；`test_versioned_events_have_contiguous_sequence_and_stable_ids` 覆蓋不同 logger instance 與 restart。

| Mutation／failure | Detection |
|---|---|
| 中間 event 刪除 | next sequence gap |
| sequence 重複／event duplicate | expected sequence／duplicate identity failure |
| event reorder | first out-of-order sequence failure |
| persisted field 修改 | canonical digest mismatch |
| malformed JSON／blank line | line-oriented typed integrity error |
| 完整 JSON 但沒有 final newline | unterminated-record error |
| unsupported schema／unknown v1 field | schema/envelope error |
| attempt 無 result | complete validation 的 dangling-attempt error |
| result 無 attempt／錯 request-action-tool-session | exact-reference/correlation error |

錯誤只回報 line/reason，不回顯 record payload；CLI 不把 invalid history 當 empty，也不產生 export destination。

## Attempt／result／session linkage

Middleware attempt append 成功後才進入 handler。若 attempt persistence 失敗，回傳 sanitized `audit_failure` 且 handler 不執行。Success、unknown tool、tool-limit denial、policy/confirmation denial、expected failure 與 exception result 都由同一 finalization path帶入 exact `attempt_event_id`。Audit result完成後，session line保存相同 `request_id`／`action_id` 及 audit attempt/result event IDs。

對應證據：

- `test_success_emits_correlated_attempt_and_result`
- `test_unknown_tool_is_denied_and_audited`
- `test_limit_denial_does_not_call_or_track_handler`
- `test_session_links_exact_audit_events_and_redacts_all_result_fields`
- `test_audit_attempt_failure_denies_before_handler_without_secret_echo`
- `test_attempt_result_exact_reference_is_verified`
- `test_dangling_attempt_and_mismatched_result_are_detected`

## Legacy／migration

- Pre-v1 record不重寫，載入為 `schema_version=0`。
- Legacy record 可 sanitized read/show/export，但整份 status 為 `legacy_unverified`。
- 既有 legacy lines 後第一筆 schema-v1 event 使用 sequence 1；legacy 必須位於 versioned history 前。
- Session legacy metadata在 load 時 sanitation；沒有自動改寫。
- Filtered export 保留來源 event ID／sequence，因此是 evidence subset，不重新編號或假裝成新的完整 primary log。
