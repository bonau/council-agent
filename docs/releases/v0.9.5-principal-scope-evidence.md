## 結論

v0.9.5 把 OpenRouter provider credential 與 Council tool authorization principal 分成不同型別與資料流。每個 Council principal 有 stable ID、kind、issuer 與 closed scope set；mandatory dispatcher 在 private handler、project policy、confirmation、filesystem I/O 與 subprocess 前重新解析 current principal 並套用 cumulative scope matrix。缺失、invalid、identity mismatch、scope insufficient 或 resolver revoke 都 fail closed。

Read-only principal 只能進入 `read_file`／`list_dir`；不能透過 `run_tests`、`run_command`、Crew wrapper、project allowlist、confirmation 或 `--yes` 間接 mutate。Scope refusal 不計為已執行的 tracker action，有 sandbox 時仍由 middleware 寫一組 correlated attempt/result 與一筆 denied session evidence。

這不是 authentication、persistent revoke/grant store 或 Trust Tier。CLI local principal 是明確 authorization declaration，不證明真人身分；session authentication、user-owned grant store 與 decision matrix 仍由 v0.9.6–v0.9.8 負責。

## Provider credential／principal 分離

```text
OPENROUTER_API_KEY
  → Pydantic SecretStr
  → OpenRouterCredential (repr redacted)
  → planning/execution/verification/escalation model builders
  → OpenRouter LLM client only

COUNCIL_PRINCIPAL_ID + COUNCIL_PRINCIPAL_SCOPES
  → strict local Principal
  → SecurityContext expected identity/current resolver
  → dispatcher scope decision
  → masked scope_authorization evidence
```

邊界證據：

- `OpenRouterCredential` 不接受空 key，`repr` 不含 secret；`make_llm` 只接受該型別並只在 model-client constructor 取出 secret。
- `run_council` 第三、第四個必要參數分別是 typed provider credential 與 `Principal`；raw key 或把 provider credential 放在 principal 位置會在 crew 建立前 `TypeError`。
- `SecurityContext` 只收到 principal／resolver，不含 provider key；crew/model builders只收到 provider credential，不含 principal scopes。
- Settings 對 provider key 使用 `SecretStr`；CLI 顯示 masked `sha256:` principal reference，不顯示 raw principal ID。
- `test_run_council_rejects_raw_provider_key_before_crews`、`test_provider_credential_cannot_substitute_for_principal`、`test_openrouter_factory_reveals_key_only_to_model_client`、`test_run_loads_read_only_principal_separately_from_provider` 覆蓋型別與載入邊界。

## Principal model

| 欄位 | Contract |
|---|---|
| `principal_id` | non-empty stable ID；不寫入 durable evidence |
| `kind` | closed enum：`local-user`、`service` |
| `issuer` | non-empty identity source；與 kind/ID 一起形成 identity |
| `scopes` | immutable `frozenset[PrincipalScope]`；string／unknown enum 不接受 |
| `audit_ref` | `sha256:` + issuer/kind/ID canonical digest prefix；stable、不可逆 |

CLI 預設以本機 OS user 形成 `local-user` principal，預設授予五種 v0.9.5 scope以保留既有 CLI tool 能力；`COUNCIL_PRINCIPAL_ID` 可指定 stable ID，`COUNCIL_PRINCIPAL_SCOPES` 可顯式縮小。Unknown scope 的 error 不回顯輸入值，pipeline 不啟動。

目前 CLI 只建立 local-user principal。`service` kind 可由 library caller 顯式建立，但沒有 service authentication、credential issuer、remote IAM／OAuth 或 persistent registry。

## Cumulative scope matrix

| Top-level action | Required scopes |
|---|---|
| `read_file`、`list_dir` | `read` |
| `write_file`、`delete_file` | `filesystem:mutate` |
| `run_tests` | `test` + `filesystem:mutate` |
| `run_command` read category | `shell` + `read` |
| `run_command` write category | `shell` + `filesystem:mutate` |
| `run_command` dangerous category | `shell` + `filesystem:mutate` + `high-risk:manage` |

`run_tests` 明確需要 mutate，因 pytest 會執行 project code；只持有 `test` 或只持有 `filesystem:mutate` 都不夠。Dangerous shell 保守累加 mutate，避免 `rm -rf` 因 dangerous precedence 隱藏 write effect。Scope 不互相隱含，必須逐項存在。

Unknown／unparseable shell input至少需要 `shell`，之後仍由既有 fail-closed analyzer拒絕；scope gate不把 unsupported action變成支援 action。

## Decision order、tightening 與 revoke

每次 `invoke()`：

1. 驗證 active `SecurityContext`；
2. 依 top-level tool/canonical command category計算 required scopes；
3. 呼叫 current-principal resolver（static principal則回傳同一 immutable value）；
4. 比對 expected issuer/kind/ID、檢查 current scopes；
5. 將 masked decision寫入 attempt evidence；
6. 只有 allow 才進入 handler的 workspace、policy、confirmation與operation gates。

Stable denial reason：

- `principal_missing`
- `principal_revoked`
- `principal_invalid`
- `principal_mismatch`
- `scope_insufficient`

`test_scope_tightening_and_revocation_apply_on_next_decision` 先以 full scope成功寫檔，再讓 resolver回傳同 identity/read-only，下一個 write立即拒絕；resolver接著回傳 `None`，下一個 read以 `principal_revoked` 拒絕。檔案只保留第一次寫入內容，tracker只有第一次成功 action。這證明 runtime 不沿用 stale scope；resolver本身仍只是 trusted in-process seam，不是 v0.9.7 persistent grant/revoke store。

Project policy與confirmation都在 scope allow之後；`test_scope_denial_precedes_project_policy_confirmation_and_process` 以 project allowlist + approve callback仍得到 scope deny，lower gate、prompt與 subprocess call count都是 0。`--yes` 只選 confirmation mode，不能授 scope或 authenticate。

## Masked audit／session evidence

Middleware result與 durable attempt/result的 `metadata.scope_authorization`包含：

- `principal_ref`（masked `sha256:` reference，缺 principal時為 null）
- `principal_kind`
- sorted `required_scopes`／`granted_scopes`／`missing_scopes`
- `scope_decision`（allow／deny）
- stable `reason`

使用 `scope_authorization` 而非 generic `authorization`，因後者在 v0.9.4 sanitizer中是 secret-bearing HTTP credential key，整個 value必須 redacted。此結構仍經 recursive sanitizer；raw principal ID、provider key或 credential-shaped tool value都不落盤。

Authorization evidence放在既有 `metadata`，沒有新增 audit top-level field，因此 v0.9.4 schema-v1 event的 canonical reconstruction／event ID維持相容。Attempt/result仍有相同 request/action/session、連續 sequence、canonical event ID與 exact `attempt_event_id`。

`test_audit_masks_raw_principal_and_provider_credential_text` 直接檢查 JSONL不含 raw principal/provider secret，兩 phase的 masked ref相同且result精確引用attempt。`test_context_without_principal_denies_and_audits_before_handler` 證明 missing principal也有 sanitized denied decision且handler未執行。

## 相容性與 migration

Library caller需顯式分開 provider與principal：

```python
provider = OpenRouterCredential(openrouter_api_key)
principal = Principal(
    principal_id="stable-caller-id",
    kind=PrincipalKind.SERVICE,
    issuer="embedding-application",
    scopes=frozenset({PrincipalScope.READ}),
)
result = run_council(prompt, preset, provider, principal)
```

Direct tool caller需在 `SecurityContext.create(..., principal=principal)` 安裝 principal。缺 principal的 context可以存在以產生可診斷 refusal，但任何 registered action都在 handler前拒絕。Crew builders也改收 `OpenRouterCredential`；raw string不再接受。
