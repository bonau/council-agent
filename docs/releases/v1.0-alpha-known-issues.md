- v1.0-alpha 前必須依序完成並發佈 v0.9.1–v0.9.9。
- v1.0-alpha 前所有 P0／P1 必須關閉，且有拒絕、旁路、無副作用與 smoke evidence；不能只標記為接受風險。
- 公開 beta 前所有 P0 必須關閉。若新增或重開 P0，立即停止公開測試。
- Trust Tier 0/1/2 runtime 屬於 v1.0-alpha 的獨立 change；v0.9.x 不得提前把 `ConfirmMode` 或 `--yes` 包裝成 Trust Tier。

## P0 — 立即阻斷

### V1-001 — 未知指令 Fail-open 與 Shell Boundary

- **狀態**：**Closed（v0.9.1；已 release/tag）**。
- **修正**：classifier 現在只接受明確 simple-command registry；未知、無法解析、shell control 與混淆 option fail-closed。接受的 action 保留 canonical argv，以 `shell=False` 執行；`cat`、`ls`、`rm`、`mv`、`cp`、`touch`、`mkdir` 的所有已識別路徑運算元在 subprocess 前經 `WorkspaceGuard`。
- **風險**：未經確認的 `read` 身分可執行實際寫入或外連動作，形成安全邊界繞過。
- **重現**：`MAN-08`、`MAN-09`、`SMK-06`、`SMK-07`。
- **關閉條件**：命令 grammar 與 canonical action 明確；未知、無法解析、混淆及高風險組合 fail-closed；分類與執行同一 action；越界與外部 sentinel 無副作用測試通過。
- **關閉證據**：[v0.9.1 shell-containment evidence](v0.9.1-shell-containment-evidence.md) 連結正向 argv、未知／複合拒絕、policy 旁路、外部 sentinel、symlink／traversal 與完整 regression 結果。
- **剩餘限制**：這仍不是 OS sandbox。允許且經 policy／confirmation 的程式可存取網路、啟動子程序或自行解讀資源；無環境／`PATH` 隔離、process-tree confinement 或 TOCTOU 防護。統一 dispatcher 仍是 V1-003／v0.9.2。

### V1-002 — `run_tests` Quoting 與 Shell Injection 面

- **狀態**：**Closed（v0.9.1；已 release/tag）**。
- **修正**：typed `path` 經 `WorkspaceGuard` 後成為單一 argv element；`args` 只經一次 `shlex.split`，保留 quoted value boundary。未知 option、未建模 path-writing option、malformed quoting 與 shell control syntax 在 process creation 前拒絕；pytest action 經 canonical policy、明確 `write` classification 與 confirmation。
- **風險**：含空白、Unicode、引號或 metacharacter 的合法輸入可能改變語意；惡意輸入可能加入額外 shell action。
- **重現**：`MAN-13`、`SMK-07`。
- **關閉條件**：執行使用 argv／受支持 grammar，不做不安全的 shell 字串重組；合法特殊路徑可測；redirect、pipeline、substitution 與額外命令 fail-closed 且無副作用。
- **關閉證據**：[v0.9.1 shell-containment evidence](v0.9.1-shell-containment-evidence.md) 連結 exact argv、空白／Unicode／引號／合法 metacharacter 路徑、args injection refusal 與 structured pytest report 結果。
- **剩餘限制**：`run_tests` 仍會執行專案程式碼，argv containment 不會隔離惡意測試；pytest args schema 有意保守，未建模 option 需先補路徑／風險模型與測試。

### V1-003／SEC-P0-002 — 無唯一 Policy Middleware／Dispatcher

- **狀態**：**Closed（v0.9.2 implementation；release branch 版本 bump／tag 仍分開執行）**。
- **修正**：六個 public tool functions、Execution Crew adapters 與 `run_council` 產品路徑都進入 `security.middleware.invoke()`。Orchestrator 只安裝一份 immutable `SecurityContext`，集中 workspace、project policy snapshot、confirmation、tracker、request/session correlation 及 optional session/audit writer；cleanup lease 也會讓 copied stale context fail-closed。
- **一致決策**：filesystem／shell private helpers 接收同一 active context；Crew wrapper 只轉接輸入／格式化結果，不再 pre-check limit、呼叫 tracker、append session 或寫 audit。`run_tests` 是一個 top-level action，不產生 nested `run_command` decision。
- **缺 context**：public direct／Crew path 都回傳 structured `security_context_missing`，不執行檔案或 subprocess。Unknown、policy／confirmation deny、limit、tool failure、exception 與 success 都由 middleware 產生 correlated result；有 sandbox 時每個 action 另有 request/action/session 相同的 attempt／result audit。
- **關閉證據**：[v0.9.2 Policy Middleware evidence](v0.9.2-policy-middleware-evidence.md) 連結 direct bypass、Crew/direct decision、stale cleanup、limit deny、no duplicate evidence、sandbox/no-sandbox e2e 與完整 regression。
- **剩餘限制**：無 sandbox 時只有 in-memory tracker/result correlation，不建立 durable audit；private Python objects 不是 hostile in-process isolation boundary。Project policy trust boundary/schema、audit integrity、principal、authentication、grant 與 Trust Tier 仍分別由 v0.9.3+／v1.0-alpha 負責。

## P1 — Alpha 前必須關閉

### V1-004／SEC-P0-004 — Project Policy Trust Boundary 與 Schema

- **狀態**：**Closed（v0.9.3 implementation；release branch 版本 bump／tag 仍分開執行）**。
- **修正**：`council.policy.yaml` 明確是 untrusted、project-owned、restrict-only 輸入。必須宣告 integer `schema_version: 1`；未知／拼錯／授權型欄位、未支援或錯誤型別 version、無版本舊檔與不合法已知欄位全部在 session／context／crew 前拒絕，不部分套用。診斷列出 path／field，但不回顯未知欄位值。
- **不可提權**：`allowed_commands` 只作額外 intersection filter；不能使 unsupported command 通過，也不能覆蓋 command/path deny、classification、containment、confirmation 或未來授權閘道。`denied_commands` 與 `denied_paths` 只能增加限制；schema 不接受 scope、authentication、grant、tier 或 bypass 欄位。
- **政策檔保護**：root／nested `council.policy.yaml` 已加入 built-in denied paths。Public read/write/delete 與受支援 shell path action 都在 operation／subprocess 前拒絕，sentinel 內容不變；project policy 無法移除這項預設。
- **關閉證據**：[v0.9.3 policy trust boundary evidence](v0.9.3-policy-trust-boundary-evidence.md) 連結 strict schema、typo／unknown／secret diagnostic、restrict-only precedence、orchestrator pre-runtime fail-fast、root／nested policy sentinel 與完整 regression。
- **剩餘限制**：這不是 OS containment。`run_tests` 會執行專案程式碼，host user 或外部程序也可改寫 workspace；更廣的 audit/control-plane 保護屬 V1-005／v0.9.4。User-owned、workspace 外且可 revoke 的 trust grant store 尚未實作，仍由 V1-008／v0.9.7 負責；project policy 不會暫代該授權來源。

### V1-005 — Audit 完整性與秘密處理不足

- **狀態**：**Closed（v0.9.4 implementation；release branch 版本 bump／tag 仍分開執行）**。
- **控制面修正**：root／nested `.council`、audit、sessions、config、reserved auth/grant path與 `council.policy.yaml` 是 immutable built-in denied paths。Public filesystem與受支援 shell path action在 I/O／subprocess 前拒絕，project policy不能移除；POSIX control dirs/files分別重申 `0700`／`0600`。
- **秘密處理**：audit/session 的 prompt、args、metadata、output與error共用 recursive sanitizer。Sensitive key、credential assignment、Bearer、JWT、常見 provider token與private-key block先遮罩再truncate；legacy show/export也sanitized。
- **完整性 substrate**：schema-v1 event有 serialized monotonic sequence、canonical content-derived `sha256:` event ID及 exact `attempt_event_id`。Strict loader偵測 gap、duplicate、reorder、content mutation、unknown envelope、malformed／unterminated line、dangling/mismatched correlation；CLI明示 `empty`／`verified`／`legacy_unverified`，invalid history fail closed。
- **關閉證據**：[v0.9.4 audit integrity evidence](v0.9.4-audit-integrity-evidence.md) 連結 multi-process writer、tamper/gap、secret matrix、shell no-process sentinel、permissions、middleware linkage及CLI refusal tests。
- **剩餘限制**：這是 v1.0 hash-chain 的可升級 substrate，不是完整 hash chain或 tamper-proof storage。沒有 predecessor link、external signature／checkpoint／immutable sink；host owner/root、project test process、external process、tail deletion或 whole-log replacement仍可超出偵測範圍。Principal、authentication、grant與Trust Tier依 v0.9.5+／v1.0-alpha處理。

### V1-006 — 缺少 Principal／API Key Scope 模型

- **狀態**：**Closed（v0.9.5 implementation；release branch 版本 bump／tag 仍分開執行）**。
- **修正**：`OpenRouterCredential` 只進 model builders；Council `Principal` 另有 stable ID、kind、issuer及closed scopes。`run_council`／CLI分開載入兩者，raw provider key或provider-as-principal在crew前拒絕；provider setting採`SecretStr`，CLI只顯示masked principal reference。
- **Scope gate**：mandatory dispatcher每個action重新解析current principal。`read_file`／`list_dir`需`read`；filesystem mutate需`filesystem:mutate`；`run_tests`需`test`+mutate；shell依read/write/dangerous累加`read`／mutate／`high-risk:manage`。Missing、invalid、identity mismatch、scope insufficient與resolver revoke全部在handler前fail closed，project policy、confirmation／`--yes`與wrapper不能提權。
- **旁路／無副作用**：read-only、test-only、mutate-only principal不能啟動`run_tests`；direct與Crew wrapper同一decision；shell缺scope時policy／confirmation helper與subprocess call count為0，filesystem/test sentinel不變。Scope tightening/revoke在下一次decision生效，不沿用stale scopes。
- **Audit**：attempt/result/session使用`metadata.scope_authorization`保存masked `sha256:` principal ref、kind、required/granted/missing scopes、decision/reason；raw principal ID與provider credential不落盤。Evidence仍在既有metadata中，保持v0.9.4 schema-v1 canonical event相容。
- **關閉證據**：[v0.9.5 principal-scope evidence](v0.9.5-principal-scope-evidence.md) 連結型別分離、scope matrix、direct／wrapper／composite bypass、no-process/sentinel、masked audit、tightening/revoke與完整 regression。
- **剩餘限制**：CLI local principal是authorization declaration，不是authentication；resolver是trusted in-process seam，不是persistent revoke store。Session authentication、user-owned trust grant store、decision matrix與Trust Tier仍分屬v0.9.6+／v1.0-alpha；hostile Python caller／host user/root與project test code不在此身分模型的隔離保證內。

### V1-007 — Session ID 不是 Authentication

- **狀態**：**Closed（v0.9.6 implementation；release branch 版本 bump／tag 仍分開執行）**。
- **修正**：process-local authentication manager 與 session record 分離；challenge/token 綁定 masked principal、canonical workspace、runtime session、purpose、exact action與期限。Challenge在credential比較前consume；step-up token在freshness／binding比較前consume，mismatch後也不可重用。Restart不恢復outstanding state。
- **產品step-up**：orchestrator固定啟用high-risk requirement。既有scope decision需要`high-risk:manage`時，dispatcher在policy/confirmation/handler前要求fresh proof。`COUNCIL_AUTH_SECRET`是獨立typed service/test verifier；缺失、expired、revoked、replayed或錯綁定均fail closed。`--yes`只選`ConfirmMode.AUTO`，不能建立或滿足authentication。
- **Audit／秘密**：success、failure、expiry、revocation、replay有schema-v1 administrative `session_auth` event；tool/session evidence只保留masked binding與challenge/token reference。Raw verifier、challenge、nonce、response與token不進audit、session、CLI console或evidence。
- **關閉證據**：[v0.9.6 session-auth evidence](v0.9.6-session-auth-evidence.md) 連結direct／Crew／orchestrator／sandbox denial、no-process/sentinel、expiry/revoke/replay/restart、secret absence及完整regression。
- **剩餘限制**：persistent user-owned verifier/grant/revoke store仍屬V1-008／v0.9.7；direct library context為相容性需明確啟用high-risk step-up。這不是Trust Tier runtime、remote SSO、hostile in-process或OS isolation。

### V1-008 — 缺少 User-owned Trust Grant Store

- **狀態**：**Closed（v0.9.7 implementation；release branch 版本 bump／tag 仍分開執行）**。
- **使用者邊界**：schema-v1 store 預設位於 `${XDG_DATA_HOME:-~/.local/share}/council-agent/trust/`，與 Agent workspace 不得重疊。現有／新建 control-plane component 會驗證 POSIX current UID、non-symlink、directory `0700`／file `0600`、安全 ancestor；ownership／permission／type／lock 不可驗證時 fail closed。
- **Exact grant**：record 綁定 masked principal、recognized canonical action、finite canonical JSON resource、closed scopes、masked creator、aware create/optional expiry、unique UUID及 retained revoke tombstone。Scope 必須是 current authenticated principal 的 subset；duplicate/conflicting/expired/revoked/corrupt/unknown schema 不採用。
- **管理 authentication**：grant／revoke 需 `high-risk:manage`，list 需 `read`，且每次都在 store API 內使用 principal/store/session/purpose/exact arguments 綁定的一次性 fresh proof。Provider key、project policy、workspace content、confirmation、`--yes`、session UUID 都不能代替 proof 或擴權。
- **原子與 audit**：exclusive inter-process lock 下重新讀取 strict state，以同目錄 `0600` temporary + file `fsync` + descriptor-relative atomic replace + directory `fsync` 提交；partial write／replace failure 保留前一完整版本。Authentication、management及 explicit lookup 寫入 user-owned schema-v1 audit，raw principal/resource/grant ID/verifier/challenge/response/token 不落 audit。
- **關閉證據**：[v0.9.7 trust grant store evidence](v0.9.7-trust-grant-store-evidence.md) 連結 ownership/mode/symlink/workspace refusal、duplicate/corruption、concurrent writer、atomic failure、authentication replay/expiry/revoke/mismatch、project/Agent bypass、persistent revoke、redaction與完整 regression。
- **剩餘限制**：grant 尚未接入 dispatcher allow/confirm/deny；Trust Tier 0/1/2、`--trust-tier` 與完整 precedence matrix 仍屬 v0.9.8/v1.0-alpha。Host owner/root、hostile in-process caller及 whole user-control-plane rollback 不在本版隔離／anti-rollback 保證內。

### V1-009 — Confirmation 與 Trust Tier 語意混合

- **現況**：`ConfirmMode.AUTO` 會自動同意需確認操作；這只描述互動方式。**`ConfirmMode ≠ Trust Tier`；`--yes ≠ 完整授權、authentication 或提權。**
- **風險**：若直接把 `AUTO` 或 `--yes` 映射成 Tier 2，policy deny、scope 或 authentication 可能被誤繞過。
- **重現**：`MAN-05`、`MAN-07`、`SMK-05`。
- **關閉條件**：完成可審查 decision matrix；deny、scope、authentication、grant 與 action risk 優先於 confirmation；所有入口有相同 reason code。

### V1-010 — Verification／Escalation Evidence 未閉合

- **現況**：Verification FAIL 後的 Escalation 會產生新輸出，但不重新 Verification；回傳 verdict 仍可能屬於舊輸出。
- **風險**：最終內容未達成功條件卻帶著過時 verdict；tool／test／policy／audit evidence 無法對應同一次 attempt。
- **關閉條件**：每次 Escalation 後重新驗證；attempt ID、最終輸出、verdict、tool summary、test exit code 與 audit correlation 指向同一嘗試；缺必要 evidence 不得 PASS。

## P2 — 文件與可維運性

### V1-011 — 發行測試文件與術語尚未驗證

- **現況**：本次已建立真人手冊、Agent checklist、smoke suite 與問題範本草稿，但尚未由獨立真人及無前置脈絡 Agent 完整走查。
- **風險**：ROADMAP、spec、README、CLI help 與 release notes 可能對「已具備」、「啟發式」及「尚未實作」使用不同語意。
- **關閉條件**：獨立執行者完成全部必跑案例；疑義與修正寫回 learning log；文件術語與產品行為一致；不宣稱現行版本有完整安全框架。

## 狀態更新規則

1. 不得因「現有測試沒失敗」直接關閉或降級問題。
2. 關閉時必須連結對應 OpenSpec change、修正 commit、正向／拒絕／旁路／無副作用測試與同一 commit 的 smoke evidence。
3. 問題重開時保留原關閉證據，新增重現環境與影響範圍。
4. P0 關閉前不得進公開 beta；P0／P1 關閉與 v0.9.1–v0.9.9 完成前不得進 v1.0-alpha。
