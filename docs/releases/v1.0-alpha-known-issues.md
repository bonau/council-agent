# v1.0 Alpha 已知問題

> 狀態：**草稿／準備階段**。基線為 v0.9.0；下列問題來自 2026-08-11 的程式、規格、測試與文件探索，尚未因本文件建立而修正。

## 發行閘門

- v1.0-alpha 前必須依序完成並發佈 v0.9.1–v0.9.9。
- v1.0-alpha 前所有 P0／P1 必須關閉，且有拒絕、旁路、無副作用與 smoke evidence；不能只標記為接受風險。
- 公開 beta 前所有 P0 必須關閉。若新增或重開 P0，立即停止公開測試。
- Trust Tier 0/1/2 runtime 屬於 v1.0-alpha 的獨立 change；v0.9.x 不得提前把 `ConfirmMode` 或 `--yes` 包裝成 Trust Tier。

## P0 — 立即阻斷

### V1-001 — 未知指令 Fail-open 與 Shell Boundary

- **現況**：classifier 只做 pattern 搜尋；沒有命中 dangerous／write pattern 的未知、混淆或組合命令預設為 `read`。`run_command` 使用 `shell=True`，只確認 `cwd` 在 workspace，**不是真 sandbox**；絕對路徑、子程序、redirect 與網路副作用不受 workspace containment。
- **風險**：未經確認的 `read` 身分可執行實際寫入或外連動作，形成安全邊界繞過。
- **重現**：`MAN-08`、`MAN-09`、`SMK-06`、`SMK-07`。
- **關閉條件**：命令 grammar 與 canonical action 明確；未知、無法解析、混淆及高風險組合 fail-closed；分類與執行同一 action；越界與外部 sentinel 無副作用測試通過。
- **暫時緩解**：只在一次性、非特權、無秘密且預設斷網的環境使用；不要把 untrusted prompt 傳給 Agent。

### V1-002 — `run_tests` Quoting 與 Shell Injection 面

- **現況**：`run_tests` 將 test path 與 `args.split()` 結果以空白重新組成字串，再交給 `shell=True`。
- **風險**：含空白、Unicode、引號或 metacharacter 的合法輸入可能改變語意；惡意輸入可能加入額外 shell action。
- **重現**：`MAN-13`、`SMK-07`。
- **關閉條件**：執行使用 argv／受支持 grammar，不做不安全的 shell 字串重組；合法特殊路徑可測；redirect、pipeline、substitution 與額外命令 fail-closed 且無副作用。
- **暫時緩解**：只測固定、無空白與無 shell metacharacter 的相對路徑；不要接受不可信的 pytest args。

### V1-003 — 無唯一 Policy Middleware／Dispatcher

- **現況**：政策、確認、tracker、session 與 audit 分散在 tools、Crew wrapper 與 orchestrator；直接呼叫低階 tool 不一定產生產品安全 audit。
- **風險**：CLI、Crew、library 或未來 Trust Tier 若只掛其中一層，可產生未授權或不可追溯旁路。
- **重現**：比對直接 `run_command`／filesystem 呼叫與完整 Execution Crew 的 audit／tracking 結果。
- **關閉條件**：所有產品 tool 呼叫經單一 dispatcher；同一份 `SecurityContext` 固定執行 context 驗證、政策、授權、追蹤、審計與執行；缺 context 或旁路 fail-closed。
- **暫時緩解**：不要把低階 library tool 暴露為受信任產品入口；audit 缺失視為阻斷，而非「沒有事件即沒有操作」。

## P1 — Alpha 前必須關閉

### V1-004 — Project Policy Trust Boundary 與 Schema

- **現況**：`council.policy.yaml` 位於 Agent 可修改的專案內；schema 無版本，且未知欄位被忽略。
- **風險**：Agent 可改寫 project policy；拼錯或未支援的安全欄位會產生控制已生效的錯誤期待。
- **重現**：`MAN-10`。
- **關閉條件**：project policy 明確為 untrusted、restrict-only；使用者授權存在 workspace 外；schema version 必填，未知欄位與未支援版本 fail-fast。

### V1-005 — Audit 完整性與秘密處理不足

- **現況**：audit 位於 `.council/audit/`；現行處理只截斷長字串，**沒有可靠 secret redaction、sequence／gap 驗證或 hash chain**。
- **風險**：Agent 可改寫或刪除安全證據；key、token 或 passphrase 可能落盤；缺漏與竄改無法可靠偵測。
- **重現**：`MAN-11`、`MAN-12`、`SMK-08`。
- **關閉條件**：控制面不可由受控 Agent 修改；巢狀欄位統一遮罩；event 有 sequence、ID 與 canonical envelope；gap、重複、部分寫入及竄改可偵測；形成可驗證 hash chain。

### V1-006 — 缺少 Principal／API Key Scope 模型

- **現況**：`OPENROUTER_API_KEY` 是 LLM provider credential，不是要求 tool action 的 principal；沒有 read、mutate、test、shell 等可驗證 scope。
- **風險**：無法把 session、authentication、grant、audit 與 revoke 綁到明確身分；所謂 read-only key 無法被產品驗證。
- **關閉條件**：provider credential 與 Council principal 分離；所有 action 先驗證 scope；read-only principal 的 wrapper／複合 tool 旁路失敗；audit 不記錄原始 credential。

### V1-007 — Session ID 不是 Authentication

- **現況**：session UUID 只供紀錄關聯，沒有 challenge、有效期、step-up、重放防護或 principal 綁定。
- **風險**：session ID 或 `--yes` 可能被誤當成高權限證據。
- **關閉條件**：authentication state 獨立於 session ID，綁定 principal、workspace、用途與有效期；過期、錯配與重放 fail-closed；秘密不落盤。

### V1-008 — 缺少 User-owned Trust Grant Store

- **現況**：沒有 workspace 外、使用者擁有、可 revoke 且綁定 principal／action／scope 的 grant 儲存。
- **風險**：若 grant 放入 workspace，Agent 可自行授權或恢復已撤銷權限。
- **關閉條件**：store 的 ownership／permission 驗證失敗即拒絕；更新具原子性；grant、expiry 與 revoke 可追溯且立即生效；project policy 不能建立 grant。

### V1-009 — Confirmation 與 Trust Tier 語意混合

- **現況**：`ConfirmMode.AUTO` 會自動同意需確認操作；這只描述互動方式。**`ConfirmMode ≠ Trust Tier`；`--yes ≠ 完整授權、authentication 或提權。**
- **風險**：若直接把 `AUTO` 或 `--yes` 映射成 Tier 2，policy deny、scope 或 authentication 可能被誤繞過。
- **重現**：`MAN-05`、`MAN-07`、`SMK-05`。
- **關閉條件**：完成可審查 decision matrix；deny、scope、authentication、grant 與 action risk 優先於 confirmation；所有入口有相同 reason code。

### V1-010 — Verification／Escalation Evidence 未閉合

- **現況**：Verification FAIL 後的 Escalation 會產生新輸出，但不重新 Verification；回傳 verdict 仍可能屬於舊輸出。
- **風險**：最終內容未達成功條件卻帶著過時 verdict；tool／test／policy／audit evidence 無法對應同一次 attempt。
- **關閉條件**：每次 Escalation 後重新驗證；attempt ID、最終輸出、verdict、tool summary、test exit code 與 audit correlation 指向同一嘗試；缺必要 evidence 不得 PASS。

## P2 — 文件與可維運性

### V1-011 — 發行測試文件與術語尚未驗證

- **現況**：本次已建立真人手冊、Agent checklist、smoke suite 與問題範本草稿，但尚未由獨立真人及無前置脈絡 Agent 完整走查。
- **風險**：ROADMAP、spec、README、CLI help 與 release notes 可能對「已具備」、「啟發式」及「尚未實作」使用不同語意。
- **關閉條件**：獨立執行者完成全部必跑案例；疑義與修正寫回 learning log；文件術語與產品行為一致；不宣稱現行版本有完整安全框架。

## 狀態更新規則

1. 不得因「現有測試沒失敗」直接關閉或降級問題。
2. 關閉時必須連結對應 OpenSpec change、修正 commit、正向／拒絕／旁路／無副作用測試與同一 commit 的 smoke evidence。
3. 問題重開時保留原關閉證據，新增重現環境與影響範圍。
4. P0 關閉前不得進公開 beta；P0／P1 關閉與 v0.9.1–v0.9.9 完成前不得進 v1.0-alpha。
