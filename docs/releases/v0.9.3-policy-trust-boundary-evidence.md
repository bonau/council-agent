## 結論

`council.policy.yaml` 現在是明確的 untrusted、project-owned、restrict-only 輸入。它只能以 allowlist intersection 或 deny union 縮小既有權限，不能建立 scope、authentication、grant、Trust Tier 或 confirmation bypass。Policy schema version 1 對 missing／unknown／typo／future／wrong-type 欄位 fail-fast；root 與 nested policy 檔也受到 product tool path deny 保護。

這份證據不宣稱 OS sandbox：`run_tests` 仍會執行 project code，host user 或其他外部程序也可能依作業系統權限修改 workspace。

## Schema 與 migration matrix

| Input | 結果 | 證據 |
|---|---|---|
| `schema_version: 1` + 三種 restriction lists | 完整載入 | `test_valid_policy_loads` |
| 無 `schema_version`／空檔 | 拒絕並提示加入 `schema_version: 1` | `test_legacy_unversioned_policy_is_rejected_with_migration`、`test_empty_file_is_rejected_as_unversioned` |
| `schema_version: 2` | 拒絕 unsupported version | `test_unsupported_policy_version_is_rejected` |
| `"1"`、`1.0`、`true` | 拒絕非 integer 1 | `test_non_integer_policy_version_is_rejected` |
| unknown `future_restriction` 與合法 deny 同檔 | 整份拒絕，不部分套用 | `test_unknown_field_rejects_entire_policy` |
| typo `denied_command` | 拒絕並指出 field | `test_misspelled_security_field_is_rejected` |
| `grant: super-secret-…` | 拒絕 `grant`，錯誤不含 value | `test_authorization_field_error_does_not_echo_secret_value` |
| known field type 錯誤 | 整份拒絕 | `test_invalid_policy_type_raises` |

舊檔 migration 只有顯式路徑：

```yaml
# v0.9.0–v0.9.2 legacy（v0.9.3 拒絕）
denied_commands:
  - "curl *"

# schema v1
schema_version: 1
denied_commands:
  - "curl *"
```

既有檔案中曾被靜默忽略的 `trust_tier`、`max_tool_calls` 或其他欄位必須移除；本版沒有 compatibility-ignore mode。

## Restrict-only decision evidence

| 嘗試 | 預期／結果 | 證據 |
|---|---|---|
| `allowed_commands: ["*"]` 搭配 unknown executable | built-in analyzer 先拒絕 `unsupported`；policy 不得准入 | `test_policy_allowlist_cannot_admit_unsupported_command` |
| allowlist 匹配 dangerous `curl`，confirmation=`refuse` | 仍拒絕且 subprocess 未啟動 | `test_policy_allowed_dangerous_still_needs_confirmation` |
| command 同時 match allow／deny | deny 優先 | `test_deny_over_allow`、`test_policy_denial_precedes_confirmation_for_canonical_action` |
| project `denied_paths` 未列 `.env`／policy file | built-in deny 仍有效 | `test_default_denylist_still_applies_with_policy`、`test_project_policy_cannot_remove_its_builtin_protection` |
| policy 帶 `trust_tier`／`grant` | schema 整份拒絕，沒有授權語意 | loader 與 orchestrator fail-fast tests |

User-owned trust authorization 與 project policy 採不同邊界：本 schema 沒有 grant 類欄位，也沒有 trust-store write/load API。Workspace 外 store、ownership、grant/revoke/expiry 屬 V1-008／v0.9.7，本版未實作。

## Fail-fast lifecycle 與 snapshot

- `run_council` 在 session、audit writer、`SecurityContext` 與 crews 之前載入 policy。
- Invalid known field 與 unknown `trust_tier` 測試都斷言 `SessionManager.create`、`SecurityContext.create`、crew builders/runners 未呼叫。
- 有效 project policy 的 middleware label 是 `project-policy/v1`；缺 policy 是 `builtin`。
- 手工配對 legacy／錯誤 label 的 context 在安裝或 invocation 前拒絕；compat derived policy view 會同步更新 policy、workspace guard 與 label。

對應測試：

- `test_run_council_unknown_policy_field_fails_before_runtime_state`
- `test_run_council_installs_and_resets_project_policy`
- `test_context_derives_policy_version_from_snapshot`
- `test_context_rejects_mismatched_policy_version`
- `test_legacy_policy_view_updates_snapshot_version`

## Policy 檔 no-side-effect 證據

Built-in denylist 同時包含 root `council.policy.yaml` 與 nested `**/council.policy.yaml`：

| Path／action | Assertion |
|---|---|
| Guard resolve root／nested policy | typed `DeniedPathError` |
| Public `read_file`／`write_file`／`delete_file` root policy | `success=False`、`rejection_reason=denied_path`、`decision=deny`，原內容不變 |
| Public `write_file` nested policy | 拒絕且原內容不變 |
| Supported shell `rm council.policy.yaml` | `denied_path`，原內容不變，`subprocess.run` call count = 0 |
| Project policy `denied_paths: []` | 無法移除 built-in policy-file protection |

對應測試：

- `test_resolve_denied_root_project_policy`
- `test_resolve_denied_nested_project_policy`
- `test_project_policy_cannot_remove_its_builtin_protection`
- `test_public_filesystem_tools_cannot_access_project_policy`
- `test_public_write_cannot_change_nested_project_policy`
- `test_supported_shell_cannot_delete_project_policy`
