## 唯一入口與旁路關閉

產品入口清單：

1. `council_agent.tools` 及 `tools.filesystem`／`tools.shell` 的六個 public functions。
2. Execution Crew 的六個 CrewAI adapters。
3. `run_council` 建立的 execution pipeline；同一 context scope 延伸至 escalation（目前 escalation 未掛 tools）。

以上 public 路徑都進入 `security.middleware.invoke()`。`crews/execution_tools.py` 只呼叫 public function 並格式化 `ToolResult`，不含 tracker limit、session append 或 audit decision。`tools.__all__` 不 export raw executor；underscore helper 要求 active context，且明確不是支援的 product authorization API。

- [`test_public_write_without_context_has_no_side_effect`](../../tests/test_policy_middleware_tools.py) 與 [`test_public_shell_without_context_starts_no_process`](../../tests/test_policy_middleware_tools.py)：缺 context 時沒有檔案／process side effect。
- [`test_direct_public_api_is_tracked_and_correlated`](../../tests/test_policy_middleware_tools.py)：direct import 仍經 dispatcher，tracker 與 result 共用 request/action ID。

## Context lifecycle 與一致 snapshot

`SecurityContext` 包含 request ID、optional session ID、workspace guard、project policy snapshot、`v0.9-unversioned` policy label、confirmation policy、tracker，以及 optional session/audit writer。Context 使用 close-on-exit lease；token reset 後，先前 copy 的 ContextVar 也因 lease closed 而 fail-closed。

對應測試：

- [`test_context_cleanup_and_copied_context_fail_closed`](../../tests/test_policy_middleware.py)：cleanup 後是 `security_context_missing`，stale copy 是 `security_context_closed`。
- [`test_session_workspace_mismatch_is_rejected`](../../tests/test_policy_middleware.py) 與 [`test_audit_session_mismatch_is_rejected`](../../tests/test_policy_middleware.py)：workspace／session／audit identity mismatch 在 operation 前拒絕。
- [`test_run_council_uses_one_security_context_snapshot`](../../tests/test_orchestrator.py)：planning、execution、verification 看見同一 context object。
- [`test_run_council_exception_closes_security_context`](../../tests/test_orchestrator.py)：exception path 也 cleanup。

## Tracker、session 與 audit correlation

Middleware 對 admitted top-level action 只寫一個 tracker summary 與一個 optional session result。`run_tests` 不遞迴呼叫 `run_command`，所以只消耗一個 call。Sandbox audit 對每個 action 寫一個 `attempt` 與一個 `result`，兩者共用 request/action/session ID；policy／confirmation／limit deny、tool failure、exception 與 success 都在 middleware result path。

對應測試：

- [`test_run_tests_is_one_top_level_action`](../../tests/test_policy_middleware_tools.py)：只有一個 `run_tests` summary，沒有 nested `run_command`。
- [`test_limit_denial_does_not_call_or_track_handler`](../../tests/test_policy_middleware.py)：limit deny 不執行 helper，仍有 correlated attempt/result audit。
- [`test_success_emits_correlated_attempt_and_result`](../../tests/test_policy_middleware.py)：兩個 phase 共用 request/action。
- [`test_wrapper_appends_to_audit_when_logger_installed`](../../tests/test_crew_tools.py)：一個 Crew action = 一個 tracker + 一個 session line + 兩個 middleware audit phases，wrapper 無重複 evidence。
- [`test_e2e_run_with_sandbox_writes_audit_events`](../../tests/test_sandbox_e2e.py)：三個真實 tool calls = 三個 summaries/session lines + 六筆 correlated audit records。

無 sandbox 時，context 的 `session`／`audit_logger` 為 `None`；middleware 與 in-memory tracker 仍生效，但不建立 `.council/`。證據見 [`test_no_sandbox_context_creates_no_durable_evidence`](../../tests/test_policy_middleware_tools.py) 與 [`test_e2e_run_without_sandbox_skips_session_files`](../../tests/test_sandbox_e2e.py)。
