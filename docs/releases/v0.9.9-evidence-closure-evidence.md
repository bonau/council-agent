## 已交付不變量

1. Initial execution 與每次 escalation 都有唯一、ordered `pipeline_attempt_id`。
2. Escalation 使用同一 plan／success criteria 重新 Verification；最多執行 `max_retries` 次，耗盡後最後 verdict 保持 FAIL。
3. `CouncilResult.execution`、`verdict`、`final_output`、`final_attempt_id` 與 `stop_reason` 只選 `attempts[-1]`；舊 execution／verdict／tool evidence 保留。
4. 一個 run 只使用一個 cumulative `ToolCallTracker` 與 `SecurityContext`；每個 attempt 只 snapshot 自己新增的 summaries，retry 不重設 tool-call limit。
5. Escalation 掛載既有 Execution Crew adapters；每個 tool 仍只經 mandatory dispatcher。
6. Dispatcher result、tracker summary、session line 與 audit attempt/result metadata 帶同一 `pipeline_attempt_id` 及既有 request/action/decision correlation。
7. 明確要求 product tool／pytest 的 request、plan 或 success criteria 缺少 current-attempt evidence 時，model PASS 會轉 FAIL。Required pytest evidence 另須 `success=True`、`exit_code=0`、`failed=0`。

## 自動化向量

| 向量 | 斷言 | 測試 |
|---|---|---|
| Initial PASS | 1 attempt、無 escalation、final ID／output／verdict 一致 | `tests/test_orchestrator.py` |
| Escalation PASS | Verification 呼叫兩次，第二次 output／verdict 成為 final，第一次保留 | `tests/test_orchestrator.py` |
| Retry exhaustion | 多次 escalation 都 FAIL 時最後狀態仍 FAIL，stop=`retries_exhausted` | `tests/test_orchestrator.py` |
| Retry disabled | `max_retries=0` 不建立 escalation，保留 initial FAIL | `tests/test_orchestrator.py` |
| Tracker partition | Cumulative tracker 保留舊 summary，attempt execution 只含本次 slice | `tests/test_verification_integration.py` |
| Required tests | Missing／incomplete／non-zero／failed evidence 強制 FAIL | `tests/test_verification_evidence.py` |
| Cross-attempt／missing decision | Attempt mismatch 或缺 request/action/decision/trust correlation 強制 FAIL | `tests/test_verification_evidence.py` |
| Text-only compatibility | 無 observable tool/test 要求時不捏造 evidence requirement | `tests/test_verification_evidence.py` |
| Model PASS override | Model 回 PASS 但缺 required `run_tests` 時 runtime verdict 為 FAIL | `tests/test_verification_evidence.py`、`tests/test_sandbox_e2e.py` |
| Sandbox retention | Initial/escalation result、tracker、session、audit 都有各自 ID，舊 evidence 保留 | `tests/test_sandbox_e2e.py`、`tests/test_trust_decision_middleware.py` |
| Direct／Crew parity | 兩入口沿用同一 dispatcher attempt／matrix evidence | `tests/test_trust_decision_entrypoints.py` |

## 接受的剩餘限制

- Evidence requirement 使用保守 lexical matching；它只能建立最低 evidence floor，不能形式化證明任意自然語言成功條件。
- 無 initialized sandbox 時有 in-memory attempt/request/action/decision summaries，但沒有 durable session/audit 檔。
- Product path boundary 不是 OS/process/network containment；`run_tests` 會執行 project code。
- Audit 有 recursive redaction、sequence、canonical per-event ID 與 exact attempt/result linkage，但沒有 predecessor link、external signature/checkpoint、immutable sink 或 anti-rollback。
- Grant store foundation 已存在但 persisted grant 尚未接產品 tool；沒有 Trust Tier 0/1/2 runtime。
