# v1.0 Beta 公開測試手冊

> 狀態：**v0.9.9 feature candidate 文件就緒／尚未開放公開 beta**。Package metadata 仍為已發佈 v0.9.8；v0.9.9 版本 bump／tag 只在後續 release branch。v0.9.x implementation 清債完成不等於 v1.0-alpha admission 或公開 beta 核准。

## 1. 先讀安全警告

Council Agent v0.9.9 candidate 不能視為安全隔離執行環境：

- `run_command` 使用受限 simple-command grammar、canonical argv、`shell=False` 與已建模 path operand containment；未知、複合、redirect、pipeline、substitution 會 fail-closed。這仍**不是 OS sandbox**，且允許的程序／`run_tests` project code 可在 host 權限內產生未建模副作用。
- `ConfirmMode` 只描述互動，`--yes` 只選 AUTO；兩者都不建立 scope、authentication、grant、Trust Tier 或提權。
- `council.policy.yaml` 是 project-owned restrict-only input；Agent 受控 tool 不能直接改寫它，但 host user、external process 或 project tests 仍可能修改。它不是授權來源。
- principal scope、high-risk step-up、user-owned grant store foundation 與 matrix-v1 已存在；persisted grant 尚未接產品 tool，沒有 Tier 0/1/2 runtime 或 `--trust-tier`。
- audit/session 有 recursive redaction；audit 有 sequence、canonical per-event ID 與 exact attempt/result linkage，但沒有 predecessor-linked／externally anchored hash chain，也不能抵抗 host owner/root rollback。
- Verification/escalation 以 `pipeline_attempt_id` 閉合 final output／verdict／tool／decision／audit evidence；必要 tool/test evidence 缺失時 fail-closed。Requirement detection 是保守 lexical rule，不是任意語意的形式證明。

**禁止**在含有真實 API key、token、SSH key、客戶資料、未公開原始碼或共享服務憑證的目錄測試。不要使用管理者帳號、`sudo`、正式環境或掛載主機家目錄。

## 2. 隔離需求

建議使用一次性 VM 或容器，並同時符合：

1. 建立新的非特權 OS 使用者，不授予 `sudo`。
2. workspace 使用新建的暫存目錄，與本機專案、家目錄及雲端同步目錄分離。
3. 預設停用外連網路；LIVE-01 才臨時開啟必要網域。
4. 只放人工建立的假資料；在 workspace 外另建 sentinel，以偵測越界副作用。
5. 不掛載 Docker socket、SSH agent、雲端 credential 目錄或套件發佈憑證。
6. 測試完成後丟棄整個 VM／容器；若不能丟棄，依第 9 節清理。

範例測試根目錄：

```bash
export COUNCIL_TEST_ROOT="$(mktemp -d)"
mkdir -p "$COUNCIL_TEST_ROOT/workspace" "$COUNCIL_TEST_ROOT/outside"
printf '不可變更\n' > "$COUNCIL_TEST_ROOT/outside/sentinel.txt"
cd "$COUNCIL_TEST_ROOT/workspace"
```

## 3. 安裝與基線紀錄

### 從已審核的 release candidate 安裝

使用發行負責人提供的固定版本與 SHA-256；不要從任意分支或未固定 URL 安裝。

```bash
python -m venv "$COUNCIL_TEST_ROOT/venv"
. "$COUNCIL_TEST_ROOT/venv/bin/activate"
python -m pip install --upgrade pip
python -m pip install "/path/to/council_agent-<固定版本>-py3-none-any.whl"
council --help
python -m pip show council-agent
```

### 從本 repo 驗證準備文件

```bash
cd /workspace
uv sync
uv run council --help
uv run pytest
```

證據必須記錄套件版本、wheel 雜湊、OS、Python 版本、測試 commit 與安裝命令。不得在證據中保存環境變數值或 credential。

## 4. 初始化一次性 workspace

```bash
cd "$COUNCIL_TEST_ROOT/workspace"
council sandbox init
council sandbox status
printf '公開測試假資料\n' > sample.txt
```

若從 repo 執行，將以下案例中的 `council` 替換為 `uv run --project /workspace council`。不要在 `/workspace` 本身執行會讓 Agent 寫檔的真人案例。

## 5. 執行案例

依序執行：

1. `SMK-00`～`SMK-09`：見 [`smoke-suite.md`](smoke-suite.md)。
2. Current candidate 的 `MAN-01`～`MAN-14`：見 [`manual-test-cases.md`](manual-test-cases.md)；檔內 v0.9.0 表格只作歷史紀錄，不是 current expectation。
3. `LIVE-01`：只有 release lead 明確核准、使用一次性低額 provider key，且前述離線案例全過時才可執行。

每個案例只能填寫 `PASS`、`FAIL`、`BLOCKED` 或 `NOT-RUN`。Current candidate 沒有預先豁免的 expected failure；「符合歷史 v0.9.0 缺陷」仍記為 `FAIL`，不能算通過。

## 6. 證據格式

每個案例建立一個遮罩後的 Markdown 紀錄：

```markdown
## <案例 ID> — <名稱>
- 基線：版本、commit、OS、Python
- 開始／結束：UTC 時間
- 前置條件：workspace 與政策檔雜湊
- 命令：已遮罩；不含 key、token、passphrase
- 預期：exit code、decision、提示、檔案與外部 sentinel
- 實際：exit code、stdout/stderr 摘要、審計事件摘要
- 副作用：workspace diff、outside sentinel 雜湊前後值
- 結果：PASS／FAIL／BLOCKED／NOT-RUN
- Issue：連結或「無」
```

最少證據：

- 完整命令與 exit code。
- 執行前後 `workspace` 檔案清單與差異。
- 拒絕案例的受保護檔案／外部 sentinel 前後 SHA-256。
- confirmation 顯示文字與使用者選擇。
- audit event 的遮罩後摘要、session ID／correlation 資訊。
- 政策檔內容與雜湊；不得包含真實秘密。

證據預設存到隔離環境外的測試收件位置。若要納入 repo，須先人工檢查並放入 `docs/releases/evidence/<version-or-stage>/`。

## 7. 通過標準

- 所有當次必跑案例皆為 `PASS`，且沒有 flaky 重跑。
- 拒絕案例沒有任何非預期副作用。
- 證據、console、session 與 audit 不含未遮罩秘密。
- 公開 beta 前所有 P0 已關閉；不得將 accepted risk 當成關閉。
- P1 已關閉或符合當次書面 beta gate；P2 有責任版本與風險說明。
- 同一候選 commit 的自動測試、OpenSpec 驗證與完整 smoke gate 通過。

## 8. 立即停止條件

遇到任一項，立即停止操作並撤銷測試憑證：

- 指令寫入、刪除或讀取 workspace 外資源。
- policy deny 被 `--yes`、confirmation 或其他入口繞過。
- 未知／混淆／複合指令以 `read` 身分執行並產生寫入、程序或網路副作用。
- audit／session／console／evidence 出現 key、token、passphrase 或其他秘密。
- audit 可被 Agent 無聲刪改，或事件缺漏無法辨識。
- 出現任一新 P0、既有 P0 重開，或測試環境與正式環境不再隔離。
- 受保護 sentinel 雜湊改變、無法確認副作用，或測試者不能解釋執行中的命令。

保留遮罩後失敗證據，不要為了「重試」刪除紀錄。使用 [`issue-report-template.md`](issue-report-template.md) 回報，安全問題不要貼到公開 issue。

## 9. 清理與撤銷

1. 停止後續 Council Agent 執行；記錄最後一個案例與 UTC 時間。
2. 撤銷 LIVE-01 使用的一次性 provider key，確認沒有其他 session 使用。
3. 先保存並人工遮罩必要證據，再移除測試 workspace 的 `.council/sessions/`、`.council/audit/` 與假政策檔。
4. 驗證 outside sentinel，保存最後雜湊。
5. 退出並刪除測試 virtualenv；最安全做法是丟棄整個一次性 VM／容器。
6. 不要使用廣泛的 `rm -rf` 範例。清理前以 `pwd`、`realpath` 與人工確認確保目標確為 `$COUNCIL_TEST_ROOT`。
7. 在測試紀錄標示 `已清理`、`憑證已撤銷` 或具體阻斷原因。

## 10. 回報

一般缺陷依 [`issue-report-template.md`](issue-report-template.md) 填寫。疑似 P0、秘密外洩或越界執行，先私下通知維護者並等待安全處理指示；不要公開 exploit、credential 或未遮罩 audit。
